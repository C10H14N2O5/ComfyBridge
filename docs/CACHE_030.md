# v0.3.0 定时丢弃缓存

## 菜单设置

主菜单 **6 管理模型与缓存 → 修改模型或缓存策略 → 选择模型 → 4 定时丢弃**。

- **空闲时长**：1～86400 的整数秒，首次建议 300 秒。
- **方式 1：ComfyUI /free**。适用于模型由 ComfyUI 管理的工作流；不要求 IndexTTS 缓存绑定。仅在远端运行和等待队列均为空时发出实例级卸载请求，会影响该实例其他工作流保持的模型。
- **方式 2：短生成卸载**。用于示例 IndexTTS 工作流：正常生成保持缓存；到期用最后实际提交的音色预设，把 `keep_models_cached` 改为 false，再执行一次短生成。短文本默认“好。”，可修改为 1～64 个非纯空白字符。

确认草稿、保存后，明确重启后端生效。编辑、导入和保存不会调用远端生成或卸载。仅关闭菜单窗口不会停止后端计时。

## 计时规则

1. 只有通过校验且成功进入队列的业务请求会重置全局计时。鉴权失败、参数错误、队列满等被拒绝请求不算活动。
2. 等所有业务排队、生成、音频发送和未解决远端任务结束后，按每个模型的 X 秒开始完整倒计时。长生成不会因超时长于 X 而被中途卸载。
3. 到期时本地或远端忙碌则延后。离线、状态不确定时不会猜测空闲。
4. 卸载提交前业务优先；卸载已经提交后，新业务进入原有有界队列，等待卸载结束，原请求总时限仍然有效。
5. 内部卸载不算新的业务活动，不会反复触发自己。一个使用周期只尝试一次卸载；明确失败或结果不明不会每隔 X 秒盲重试。该模型再次真实提交业务生成后建立新周期。
6. 重启先核对旧任务；对身份匹配且仍待清理的缓存重新等待完整 X 秒，不补发停机期间的“错过”操作。改变远端地址或替换/删除预设时，不用新图猜测旧缓存，需一次新业务调用建立当前归属。
7. 排空停止后不再启动新的卸载；已提交的任务继续按账本处理。强制停止不终止远端任务、不删除账本。

## 两种方式的边界

### /free 不是按 model 精确卸载

发送 `POST /free`，请求体为 `{"unload_models":true,"free_memory":true}`。原生接口返回 200 空响应体，表示设置卸载标志，不证明显存已经释放。

同一实例多个 `/free` 模型合并一次请求；最先到期的模型可能提前卸载其他模型。不同 model ID 不构成显存隔离。队列查询与发送之间无法锁住其他客户端，共享 ComfyUI 实例仍存在竞态。

绕过 ComfyUI 管理器的插件全局缓存不保证被 `/free` 清除。程序不会根据显存猜测“是否成功”，也不在失败后自行切换为付出 GPU 开销的短生成。

### 短生成需要共享缓存约定

同一 model 下的所有音色预设应使用同一套可卸载缓存。用户已测试：相同工作流副本 A/B，参考音频和文本不同，先 A 保持缓存、再 B 丢弃缓存，能够卸载。此结果不保证不同权重或不同插件的缓存互通；这类工作流应登记不同 model。

本版短生成支持已知 `IndexTTS25BaseNode` 和 `IndexTTS25CacheControlNode` 的有效绑定，以及经过校验的整数 seed 输入。每次内部卸载使用持久化分配的不同 seed，避免重复卸载图命中旧执行结果。源模板、业务生成种子不被修改。

短生成会真实消耗 GPU 时间，可能需要重新加载模型。中间层不下载、转码或返回它的音频，但工作流的 SaveAudio 仍可在 ComfyUI 端产生文件和历史记录；程序不删除这些远端产物。

## 配置示例

这是模型条目，不是可单独启动的完整配置：

```json
{
  "id": "index-tts-2.5",
  "cache_policy": "idle_release",
  "idle_release": {
    "seconds": 300,
    "method": "workflow",
    "text": "好。"
  }
}
```

`method` 取 `free` 或 `workflow`；`free` 不使用 `text`。其他策略保持 `inherit` / `keep` / `release`，不携带非空 `idle_release` 设置。旧版有效配置在新版中继续可用；旧版程序不能读取新策略，回退前先在新版改回旧策略并保存。

## 观察与恢复

Monitor 显示倒计时、等待远端空闲、卸载中、完成/请求受理、失败/不确定等状态。流程完成不等于已测得物理显存归零。

短生成与业务生成一样，先持久化提交意图，再只 POST 一次；结果不明时核对队列/历史，保留容量，不自动重发。自行核对 ComfyUI 后，可使用现有高级菜单人工确认放弃核对。人工确认不是远端终止证据。

`/free` 不具有 prompt ID，也无法用生成历史证实；其网络失败单独标记为结果不明，不永久阻塞业务，不自动重发。
